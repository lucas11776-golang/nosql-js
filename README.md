# @flyer/nosql

A high-performance, embedded, serverless NoSQL document database engine for Node.js. Built on a robust Rust core and exposed through fast, fully asynchronous Node-API (NAPI-RS) bindings.

`@flyer/nosql` provides a MongoDB-like interface for managing schemaless document collections stored in a single, local database file. It requires no external background database process to run, making it ideal for desktop applications (such as Electron), serverless functions, embedded systems, local CLI tools, and light/medium production workloads.

---

## Features

- **Blazing Fast**: Engineered with a high-performance Rust storage engine under the hood.
- **Embedded & Single-File**: Operates entirely within your application process; saves all collection data into a single local file.
- **Fully Asynchronous**: Every database and collection operation returns a native JavaScript `Promise` to avoid blocking the event loop.
- **Familiar API**: Simple, intuitive MongoDB-like document CRUD (Create, Read, Update, Delete) methods.
- **TypeScript First**: Ship with complete, autogenerated `.d.ts` typings for full IDE auto-completion and type safety.

## Quick Start

Here is a complete, step-by-step example demonstrating how to open a database, create collections, insert, query, update, and delete documents.

```typescript
import { Database } from '@flyer/nosql';

interface User {
  _id?: string;
  name: string;
  email: string;
  age: number;
  tags?: string[];
}

async function main() {
  // 1. Open or create the database at a local file path
  const db = await Database.open('data.db');
  console.log('Database opened successfully!');

  // 2. Check and create a collection
  const hasUsers = await db.has('users');
  if (!hasUsers) {
    await db.create('users');
    console.log('Created collection "users"');
  }

  // 3. Get a reference to the collection
  const usersCollection = await db.collection('users');

  // 4. Insert a single document
  const insertOneRes = await usersCollection.insertOne({
    name: 'Alice Smith',
    email: 'alice@example.com',
    age: 28,
    tags: ['developer', 'runner']
  });
  console.log('Inserted Alice. ID:', insertOneRes.insertedId);

  // 5. Insert multiple documents
  const insertManyRes = await usersCollection.insertMany([
    { name: 'Bob Jones', email: 'bob@example.com', age: 34 },
    { name: 'Charlie Brown', email: 'charlie@example.com', age: 22 }
  ]);
  console.log('Inserted multiple users. Results:', insertManyRes);

  // 6. Find a single document with type safety
  const alice = await usersCollection.findOne<User>({ name: 'Alice Smith' });
  console.log('Found Alice:', alice);

  // 7. Find multiple documents matching a filter
  const allDevelopers = await usersCollection.find<User[]>({ tags: 'developer' });
  console.log('All developers:', allDevelopers);

  // 8. Update matching documents
  const updateRes = await usersCollection.update(
    { name: 'Alice Smith' },
    { age: 29, tags: ['developer', 'runner', 'reader'] }
  );
  console.log(`Matched ${updateRes.matchedCount} and modified ${updateRes.modifiedCount} documents.`);

  // 9. Delete documents
  const deleteRes = await usersCollection.delete({ name: 'Charlie Brown' });
  console.log(`Deleted ${deleteRes.deletedCount} documents.`);

  // 10. List all collections in the database
  const collections = await db.list();
  console.log('Collections in database:', collections);

  // 11. Close the database connection when done
  await db.close();
}

main().catch(console.error);
```

## API Reference

### `Database`

The primary class used to manage database files, connections, and collection schemas.

#### Static Methods

##### `static open(path: string): Promise<Database>`
Opens an existing database file or creates a new one if it does not exist at the specified local filesystem path.
- **Parameters:** 
  - `path`: The absolute or relative path to the database file.
- **Returns:** `Promise<Database>` - A promise resolving to the database instance.

#### Instance Methods

##### `collection(name: string): Promise<Collection>`
Retrieves a handle to an existing collection in the database.
- **Parameters:**
  - `name`: The name of the collection.
- **Returns:** `Promise<Collection>` - A handle for executing operations on the collection.

##### `create(collection: string): Promise<void>`
Explicitly creates a new collection in the database.
- **Parameters:**
  - `collection`: The name of the new collection.
- **Returns:** `Promise<void>`

##### `rename(collectionOld: string, collectionNew: string): Promise<void>`
Renames an existing collection.
- **Parameters:**
  - `collectionOld`: The current name of the collection.
  - `collectionNew`: The desired new name for the collection.
- **Returns:** `Promise<void>`

##### `delete(name: string): Promise<void>`
Permanently deletes (drops) a collection and all of its documents from the database.
- **Parameters:**
  - `name`: The name of the collection to delete.
- **Returns:** `Promise<void>`

##### `has(collection: string): Promise<boolean>`
Checks if a collection with the specified name exists in the database.
- **Parameters:**
  - `collection`: The name of the collection.
- **Returns:** `Promise<boolean>` - `true` if it exists, otherwise `false`.

##### `list(): Promise<Array<string>>`
Retrieves a list of all collection names currently stored in the database.
- **Returns:** `Promise<Array<string>>` - An array of collection name strings.

##### `close(): Promise<void>`
Closes the database handle, ensuring all pending operations are finalized, caches are flushed, and file descriptors are safely released.
- **Returns:** `Promise<void>`

### `Collection`

Represents an active collection of JSON-like documents. All operations on a `Collection` are fully async.

#### Instance Methods

##### `insertOne(doc: any): Promise<InsertResult>`
Inserts a single document into the collection.
- **Parameters:**
  - `doc`: The document object to insert. It can be any valid JSON-serializable object.
- **Returns:** `Promise<InsertResult>` - An object containing the identifier of the inserted document.

##### `insertMany(docs: Array<any>): Promise<Array<InsertResult>>`
Inserts multiple documents into the collection in a single operation.
- **Parameters:**
  - `docs`: An array of document objects to insert.
- **Returns:** `Promise<Array<InsertResult>>` - An array of `InsertResult` objects representing each inserted document.

##### `findOne<T>(filter: any): Promise<T>`
Queries the collection and returns the first document matching the filter.
- **Type Parameters:**
  - `T`: The expected shape/type of the returned document.
- **Parameters:**
  - `filter`: A JSON-like query criteria to match against documents.
- **Returns:** `Promise<T>` - A promise resolving to the matched document (or `null`/`undefined` if no matching document is found).

##### `find<T>(filter: any): Promise<T>`
Queries the collection and returns all documents matching the specified filter.
- **Type Parameters:**
  - `T`: The expected type of the results (typically structured as an array, e.g., `User[]`).
- **Parameters:**
  - `filter`: A JSON-like query criteria to match against documents. Pass an empty object `{}` to retrieve all documents.
- **Returns:** `Promise<T>` - A promise resolving to the collection of matched documents.

##### `update(filter: any, update: any): Promise<UpdateResult>`
Updates all documents matching the given filter.
- **Parameters:**
  - `filter`: The query criteria to select documents for updating.
  - `update`: The update operations or document payload to apply to matching documents.
- **Returns:** `Promise<UpdateResult>` - Summary details of the matched and modified counts.

##### `delete(filter: any): Promise<DeleteResult>`
Deletes all documents matching the given filter criteria from the collection.
- **Parameters:**
  - `filter`: The query criteria to select documents for deletion.
- **Returns:** `Promise<DeleteResult>` - Summary containing the number of deleted documents.

### Auxiliary Interfaces & Classes

These supporting types describe the shapes of outcomes from document manipulation operations.

#### `InsertResult`
Returned when documents are successfully inserted.
```typescript
interface InsertResult {
  insertedId: any; // Unique identifier assigned to the inserted document
}
```

#### `UpdateResult`
Returned when documents are updated.
```typescript
interface UpdateResult {
  matchedCount: number;  // The number of documents that matched the filter
  modifiedCount: number; // The number of documents that were successfully updated
}
```

#### `DeleteResult`
Returned when documents are deleted.
```typescript
class DeleteResult {
  deletedCount: number; // The number of documents deleted from the collection
}
```

#### `RecordId`
Represents a internal-level location tracking mechanism of a document within the storage page engine.
```typescript
interface RecordId {
  pageId: number; // The storage page index
  slotId: number; // The specific slot within the storage page
}
```
